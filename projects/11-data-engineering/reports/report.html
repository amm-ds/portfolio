11 — Data Engineering: pandas vs Polars vs DuckDB vs sqlite

Protocol

Warm wall time: median of in-process repeats (see params.yaml repeats), timed WITHOUT tracemalloc so the tracer never inflates the measured region; cold reads: one fresh subprocess per IO cell (OS page cache not dropped); peak RSS: fresh-subprocess ru_maxrss high-water; tracemalloc peak: one dedicated untimed repeat per cell under tracemalloc (full-protocol runs only; the diagnostic pass is never part of the wall median); determinism gate: every repeat, traced pass and probe returns identical canonical rows (ints/strings/dates exact; floats within 1e-5 relative of the 6-significant-digit canonical form — parallel summation order). sqlite3 (stdlib) answers each task by loading the prepared file into an in-memory database via pandas inside the timed cell — the load is the documented conversion tax — and has no write_parquet (no stdlib parquet writer), so that cell is n/a.

Scalability protocol

Scalability study: seeded synthetic tracks at 1,000,000, 3,000,000, 10,000,000 rows over the 5 most discriminating tasks (read_csv, groupby, join, window, filter); median of 2 warm in-process repeats, no fresh-process probes; determinism gate between repeats; sqlite converts the files into its in-memory database inside each timed cell (the documented conversion tax).
