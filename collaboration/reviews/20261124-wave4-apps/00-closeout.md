### Structural & infra audit

Compared `pyproject.toml`, `.env.example`, `infra/` (Dockerfile + docker-compose),
and `README.md` across both apps. Findings and actions:

- **Added `## Common errors` to both READMEs.** This was the one genuinely
  missing skeleton element (house rule in `docs/engineering/repo-conventions.md`:
  every README carries the `| symptom | cause | fix |` table). Everything else
  mapped section-by-section between the two files (quickstart, HTTP surface,
  evals, limits, specs).

    `## Common failures` table in `specs/operations.md` (db 503, Ollama
    `APIConnectionError`, 401, stale conversation 404, settled approval 404),
    with executable fixes.

    failure modes, verified against source status codes
    (`api/identity.py` returns 401 for missing/invalid identity): bare uvicorn
    has no worker, `document_busy` 409, per-page failure with document
    completion, missing dev identity, dev headers rejected in production.

  share ruff/mypy/pytest configuration shape, workspace isolation, and
  healthchecked compose stacks. Remaining differences are domain-specific and
  intentional (doc-intel adds `**/scripts/**` per-file ignores, the pydantic

  has the optional `[embeddings]` extra). Compose stacks differ by design

  leased worker, localhost-bound port).

### Gate fixes (pre-existing mypy strict failures, committed state)

Both apps' `tests/test_error_contract.py` had latent typing bugs (parameter
annotated `TestClient` instead of a response type; `asyncio.run` on a
`Response | Awaitable[Response]` union; `.body.decode()` where starlette types
`body` as `bytes | memoryview`). `apps/document-intelligence/tests/test_api_rate_limit.py`
indexed a `dict[str, object]` value. Fixed with version-agnostic typing
(a `_JsonBody` Protocol, `cast` on the exception-handler signature, an
`async` invoke wrapper, `bytes(response.body)` first). No behavior changed;
the error-contract assertions are untouched.
