# Architecture proposal: verifier cascade, DEV calibration

Date: 2026-11-20
Designer: Claude Code
Status: approved (offline step only)
Source design brief: `collaboration/designs/20261120-verifier-cascade-dev/01-design-brief.md`

## Decision

Score each of the 194 calibration claims by a cascade:
1. MiniCheck score `s` (committed, `reports/verifier_challenger/predictions.jsonl`).
2. If `s >= t_hi`: accept. If `s <= t_lo`: reject. Otherwise defer.
3. Deferred claims go to the local judge (`qwen2.5:3b`, run once on all 194 claims and cached). Supported verdict accepts; unsupported verdict rejects.

Thresholds `(t_lo, t_hi)` are chosen only on DEV, by 5-fold cross-validation over a fixed grid.

## System shape

```text
predictions.jsonl (MiniCheck score per claim, committed)  ─┐
local judge verdict per claim (cached, run once)           ─┴→ cascade(t_lo, t_hi)
  → decision per claim → FA(strict), FR, deferred share
  → DEV 5-fold CV for selection; full-DEV fit for final thresholds
  → one descriptive TEST reading
```

## Contracts and data ownership

- Grid: `t_lo` and `t_hi` drawn from the sorted unique DEV scores, with `t_lo < t_hi`. Grid is generated by one fixed function and written to the metrics file.
- Fold assignment: stratified 5-fold over DEV, seed 42, written to a committed file before scoring.
- Qualifying rule: cross-validated DEV FA over unsupported claims `<= 0.10` AND cross-validated DEV FR over supported claims `<= 0.10`. Among qualifying bands, lowest deferred share; ties to lower FA.
- Outputs: `reports/verifier_cascade_dev/{metrics.json, predictions.jsonl, report.md}`. New files only.

## Alternatives considered

| Alternative | Why rejected |
|---|---|
| Choose thresholds on TEST | Forbidden; TEST already used once |
| Re-scan thresholds after seeing the first TEST reading | Forbidden by the frozen rule |
| Use the committed hosted judge predictions for the middle band | Hosted predictions cover only 184 of 194 claims for one run, and the coverage is not complete |
| Run a hosted judge on the middle band | Costs money; not approved |

## Failure modes and limits

| Failure or limit | Detection | Behavior |
|---|---|---|
| Ollama not running | Judge call fails | Stop and report; no substitute judge |
| Local judge output unparseable | Parse check per claim | Count and report; treat unparseable as deferred-to-reject, state it |
| No band qualifies on CV | Rule check | Report failure; no re-scan |
| Small DEV (96 claims) | Wilson intervals reported | Result is directional |

## Migration and rollout

1. Freeze the rule and fold assignment, commit, record sha256.
2. Cache the local judge verdicts on all 194 claims.
3. Run CV selection on DEV. Fit final thresholds on full DEV.
4. One descriptive TEST reading.
5. Report to owner. No copy change.

## Observability and verification

- Metrics: grid size, CV results per band, chosen band, full-DEV fit, TEST reading, deferred share, unparseable count, Ollama model digest.
- Tests: fold assignment disjoint and covers DEV; cascade decision function handles boundary scores; selection code reads DEV rows only (asserted).
- Gates: `uv run pytest -q projects/01-rag-agent`, `ruff check`, `ruff format --check`, `mypy` on new code, `uv run python scripts/check_headline_numbers.py`, `uv run python scripts/check_docs.py`.

## Rollback

- Safe rollback point: commit before the cascade harness. Deleting `reports/verifier_cascade_dev/` and the harness module reverts it.
