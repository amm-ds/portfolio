## Evidence limitation (read first)

Both reports were produced by an older runner format: each failed row is
`| case | kind | grader | FAIL:  |` with an **empty** reason note, and neither
file carries the current runner's `## Failure diagnostics` section (the
answer text, tool traces, citations, and sent messages of those runs are not
committed anywhere in the repository — checked `reports/`, `specs/`, and the
umbrella `evals.md`).

Because the model's actual outputs are not committed, the **cause** of each
failure (grader error vs model error vs tool error) cannot be determined from
committed evidence. Per the handoff's stop rule, every failed assertion is
listed as **unclassified** below rather than guessed. The factual grouping
that IS committed — which grader failed, and what that grader checks — is
reported per run.

## What each failed grader checks (committed logic, `src/agent_chat/evals/graders.py`)

- `AnswerKeywords` — every expected keyword group has at least one alternative
  present in the final answer text.
- `RefusalGraceful` — a normalized refusal (marker or "no … tool … available")
  that does not contain case-forbidden fragments; run errors also fail it.
- `CitationsWhenGrounded` — every citation quotes its own claimed source
  passage (requires non-empty citations).
